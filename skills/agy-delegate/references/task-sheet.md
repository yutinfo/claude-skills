บรรทัด "วิธีทำงาน" สำคัญเป็นพิเศษกับ agy: headless ถามสิทธิ์ไม่ได้ ถ้าโมเดลพยายามใช้คำสั่งที่ไม่ได้อนุญาต รอบนั้นจะจบแบบไม่มีผลลัพธ์ (เสียโควตาฟรี)

## เทมเพลตงานที่มีหน้าจอ (เว็บ / UI / canvas / 3D)

ใช้เทมเพลตข้างบน แล้วเติมช่องเหล่านี้ **ทุกช่องบังคับ** ช่องไหนไม่เกี่ยวให้เขียน "ไม่มี" พร้อมเหตุผลสั้น ๆ

```text
ขนาดจอ — 1440x900, 1280x720, 390x844 [+ อื่น ๆ]; ไม่มีการเลื่อนแนวนอนทุกขนาด
กรอบพื้นที่ — ต่อฉาก/บท: [วัตถุ] อยู่ใน x a–b%, y c–d% ของจอ; ห่างข้อความ ≥ [24]px; ตลอดช่วงเลื่อน [เริ่ม–จบ] ไม่ใช่แค่จุดพัก
กลไกการจัดวาง — อะไร fixed / sticky / ไหลตามหน้า; ฉากที่เนื้อหาสูงกว่าจอ: วัตถุอยู่ในช่องไหนของ DOM และเลื่อนไปกับหน้าหรือหยุดตรงไหน
เทสต์กรอบ — เทสต์ที่คำนวณ bounding box (ฉายจากกล้องจริงถ้าเป็น 3D) ที่ทุกขนาดจอ × จุดเลื่อนอย่างน้อย [เริ่ม, กลาง, จบ] ของแต่ละฉาก แล้วเทียบกับกรอบข้างบน
สถานะอื่น — reduced motion, ไม่มี WebGL/JS, โหลดช้า, ลาก/แตะ/คีย์บอร์ด: ผลที่คาดของแต่ละอัน
ภาพที่ต้องได้ — สี hex, ความสว่าง/contrast ตัวเลข, จำนวนชิ้นที่ต้องนับได้ในภาพ (เช่น "เห็นเส้นแบ่งครบ 11 กลีบ"); ข้อความ contrast ≥ 4.5
ภาษาไทย — วลีในหัวเรื่องที่ห้ามตัดกลาง: [...] (span nowrap); ไม่ล้นที่ 360px
ส่งมอบ (เพิ่ม) — หัวข้อ "สิ่งที่ยังไม่ได้ตรวจด้วยตา" แยกจากสิ่งที่ทำ; ห้ามเขียนว่าภาพถูกต้องจากเทสต์อย่างเดียว
```

ใบแก้ภาพ: `N. <ไฟล์ภาพ>: อาการ → ต้นเหตุ → ค่า/กลไกที่ต้องการ` และ "เปิดภาพด้วยเครื่องมืออ่านไฟล์ก่อนแก้"

ช่องที่ทำให้งานพลาดจริงมากที่สุดคือ **กลไกการจัดวาง**: ใบงานที่เขียนแค่ "วางวัตถุให้พ้นข้อความ" ได้ตำแหน่งถูกที่จุดพัก แต่พอเนื้อหายาวกว่าจอเลื่อนผ่าน canvas ที่ fixed วัตถุก็ทับหัวข้อและตาราง ที่แก้ได้คือระบุกลไก เช่น "สองคอลัมน์ ช่องขวา sticky และผูกตำแหน่งวัตถุกับ getBoundingClientRect ของช่องทุกเฟรม"
